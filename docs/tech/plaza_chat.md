- UI: `client/online/plaza_chat.gd`, attached by existing PlazaClient CanvasLayer. Bottom-right collapsible plain-text log/input/send;40 lines in client memory, no persistent history. Uses hub shortcut UI scale for desktop/mobile landscape;44px targets, keyboard lift when supported, hides log/header when keyboard leaves little height. Hides outside plaza or under hub panels. Typing blocks hub movement;Esc releases input focus.
- Transport: existing plaza Nakama socket,opcode3 request `{text}`,opcode4 server echo `{name,text,at}`,opcode5 rate-limit response. Name comes from server-loaded profile/session membership, not request. Server only broadcasts inside the authoritative match. Reconnect/channel exit clears visible log; no local optimistic echo.
- Bounds:160 Unicode codepoints,1024-byte request ceiling,exact one-field schema,no control/bidi-override characters. Per-member token bucket3 burst,refill1/second;at most one chat attempt/member/tick. Independent from movement's one-update/tick budget. No storage/economy modifications or per-message database calls.
