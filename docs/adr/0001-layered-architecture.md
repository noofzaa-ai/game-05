# ADR 0001: แยกเกมเป็นชั้น (logic / client / data) และให้เซิร์ฟเวอร์รันตรรกะด้วย Godot headless

สถานะ: ยอมรับแล้ว (director, 2026-10-03)

## บริบท
เกมเป็นออนไลน์บนเว็บ มีของฟาร์มและ PvP ต้องให้เซิร์ฟเวอร์เป็นผู้ตัดสินเพื่อกันโกง และต้องทดสอบได้โดยไม่ต้องมีหน้าจอ
ทีมเล็ก จึงต้องเลือกวิธีที่ลงทุนน้อยแต่ไม่ล็อกตัวเอง

## การตัดสินใจ
1. แยกโค้ดเป็นชั้น:
   - `logic/` กติกาเกมล้วนๆ (การเคลื่อนที่ การชน การจำลองแบบ tick คงที่ การอ่านข้อมูลแมพ) **ห้าม** อ้างถึงโหนด ภาพ ปุ่ม UI หรือ `client/`
   - `client/` วาดภาพ อ่านปุ่ม เมนู กล้อง เอฟเฟกต์ ใช้ `logic/` ได้ แต่ `logic/` ไม่รู้จัก `client/`
   - `data/` เนื้อหาเป็นไฟล์ (ตอนนี้: แมพ; ต่อไป: ท่าต่อสู้ ไอเทม ตารางดรอป โหมด)
   - ฐานข้อมูลอยู่ฝั่งเซิร์ฟเวอร์เท่านั้น ไคลเอนต์ไม่คุยกับฐานข้อมูลตรง (เฟส 3)
   - map editor แยกเป็นเครื่องมือของตัวเอง ใช้รูปแบบไฟล์แมพเดียวกัน (เมื่อมีหลายแมพ)
2. ตรรกะเกมเขียนด้วย GDScript และเซิร์ฟเวอร์รัน **Godot แบบ headless** ด้วยโค้ดชุดเดียวกับไคลเอนต์
3. การเคลื่อนที่ใช้การคำนวณของเราเอง (กล่อง AABB + tick 60 ครั้ง/วินาทีคงที่) ไม่ใช้ฟิสิกส์ของเอนจิน เพื่อให้ผลเหมือนกันทุกเครื่องและทดสอบได้

## เหตุผล
- ผลลัพธ์ของเซิร์ฟเวอร์กับไคลเอนต์ (ทำนายล่วงหน้า) ตรงกัน เพราะใช้โค้ดเดียวกัน
- ทดสอบตรรกะได้เร็วโดยไม่เปิดหน้าต่าง (`tests/`)
- เพิ่มแมพ/ท่า/ไอเทมโดยไม่ต้องแก้โค้ด
- ภาษาเดียว ทีมเล็กดูแลไหว

## ข้อแลกเปลี่ยน (ยอมรับแล้ว)
- ตรรกะผูกกับ Godot/GDScript: ถ้าเปลี่ยนเอนจิน ต้องเขียนชั้น `logic/` ใหม่ แต่ `client/` กับ `data/` ย้ายง่ายกว่า (data เป็นไฟล์ธรรมดา)
- ฟิสิกส์เขียนเอง ต้องดูแลเอง (ตอนนี้รองรับเฉพาะกล่อง ซึ่งพอสำหรับเลน บันได แท่น)

## กฎที่ตรวจอัตโนมัติ
`tests/test_architecture.gd` ล้มทันทีถ้าไฟล์ใน `logic/` อ้างถึงโหนด/ภาพ/ปุ่ม/`client/`

## เส้นทางขยาย
- กฎใหม่ (ต่อสู้ ของดรอป สถานะ) = คลาสใหม่ใน `logic/` ที่ `GameSim.tick()` เรียกตามลำดับ ผลที่ไคลเอนต์ต้องรู้ใส่ใน `events`
- ปุ่มใหม่ = ฟิลด์ใหม่ใน `SimInput` + แมปใน `client/input_reader.gd`
- ออนไลน์ = ส่ง `SimInput` ไปเซิร์ฟเวอร์ รับ `GameSim.snapshot()` กลับมาวาด
- ทางเลือกในอนาคตถ้าโตเกิน: ย้ายเซิร์ฟเวอร์ไปภาษาอื่นโดยใช้ `logic/` เป็นสเปก (จะทำก็ต่อเมื่อจำเป็นจริง)
