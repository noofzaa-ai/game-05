## 2. กติกา git (ทำทุกครั้ง)

1. **Branch policy (Boss 2026-10-17):** แยก branch ตาม scope หลัก ใช้ `codex/online-coop` ต่อเนื่องสำหรับงาน online co-op ไม่แตก branch/push ย่อยทุก milestone หรือเครื่องมือประกอบ
2. **รุ่นทดสอบ k3s อยู่ที่ `develop`:** ก่อนเริ่มงาน fetch และตรวจ `origin/develop` เพื่อรับงานร่วมกัน เมื่อพร้อมทดสอบให้รวม scope ที่ผ่านเทสต์เข้า `develop` โดยไม่ทับประวัติหรือใช้ force push
3. **จอง scope ในหัวข้อ 4 ก่อนแก้:** อัปเดตใน branch หลักของงาน ไม่ต้องสร้าง commit/push จองงานแยกทุกงานย่อย ถ้าไฟล์มีอีกฝั่งถืออยู่ให้ประสานก่อน
4. **ก่อน push:** รันเทสต์ทั้งหมดพร้อม timeout และตรวจ stderr, อัปเดตหัวข้อ4/5/6 และ PROGRESS เมื่อมีการตัดสินใจสำคัญ; fetch และตรวจงานใหม่บน develop ก่อนรวม ไม่ rebase scope ไป main เก่าทุกครั้ง
5. **รวมเข้า `main` ผ่าน Pull Request เท่านั้น** ให้มีการรีวิวก่อนรวม ห้าม force push main/develop และห้ามถือว่ารุ่นที่อยู่บน scope branch ถูก deploy แล้ว
6. Branch/PR ย่อยเดิมเก็บเป็นประวัติได้ งานใหม่ให้ต่อใน scope หลัก และระบุ commit ของ develop ที่ใช้ build/deploy ทุกครั้ง
